Continuous control monitoring

How the collector runs itself

The evidence collector started as a script on one laptop. This layer turns it into a control that checks itself every day, with no stored credentials and no one in the loop. A control checked once by hand is a screenshot. A control checked on a schedule is monitoring.

Deep dive: the Docker layer → The control itself →

01 Why this layer exists

The local script proved the logic. But as a way to actually run a control, it had three weaknesses. Each one is what this layer removes.

Runs on one laptop
Docker seals the script and its dependencies into one image that behaves identically on any runner, server, or cluster.
Someone has to remember
GitHub Actions runs it on a schedule with nobody in the loop, so evidence is produced whether or not anyone thinks to collect it.
Needs a stored key
OIDC lets GitHub prove its identity to AWS for a single run, so there is no long-lived credential sitting in GitHub to leak.

02 The pipeline, one run

Every day at 16:00 UTC (or on a manual trigger), one workflow run flows left to right. Nothing here can write to AWS.

Trigger
Daily cron, or manual dispatch. Runs on main only.
OIDC → STS
GitHub signs a short-lived token. AWS trades it for ~1-hour credentials scoped to one role.
Container
Build and run the distroless, nonroot image. No credentials baked in.
Read-only collect
List buckets, read encryption + tags, describe KMS keys. Five read-only permissions.
Evidence artifact
JSON, CSV, and the exception register, uploaded and kept 30 days.

03 The credential change that matters

This is the part worth pausing on. The old way and the new way both let GitHub call AWS. Only one of them leaves a secret lying around.

Before · stored key

A long-lived access key in GitHub

You paste an IAM user's permanent access key into GitHub secrets. It never expires.

If it leaks, it works for anyone, anywhere, until a human notices and revokes it by hand.

After · OIDC

A signed token, good for one run

GitHub presents a token it signs itself. AWS trusts it because a trust policy pins it to StringEquals this exact repo on main — no wildcards.

AWS returns credentials that expire in about an hour. Nothing permanent is stored, so there is nothing to leak.

Bonus: cleaner audit trail

Each run assumes the role with a unique session name, gha-evidence-<run_id>. In CloudTrail every API call is attributable to a specific workflow run, instead of every run looking like the same shared identity.
